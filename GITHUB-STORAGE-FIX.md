# GitHub storage and GitHub Pages data layout (v4)

GitHub Pages configured for `main` → `/docs` can serve only files under `docs/`. The v4 data layout therefore has explicit publishing paths:

- `data/github/YYYY-MM-DD.json`: canonical GitHub Actions history.
- `data/merged/YYYY-MM-DD.json`: daily compact two-source merge.
- `data/index.json`: date index generated by the GitHub workflow.
- `docs/data/github/`: published copy of GitHub runner history.
- `docs/data/merged/`: published merged snapshots.
- `docs/data/cloudflare/`: written directly by the Cloudflare Worker.
- `docs/data/index.json`: published date index.

## Independent write ownership

GitHub Actions does **not** stage or copy `docs/data/cloudflare/`. Cloudflare does not write to the GitHub Actions `data/github/` or `data/merged/` paths. Both automations can commit to `main` without trying to replace the same daily history file. The workflow rebases and retries pushes without force-pushing.

## Worker secret

The Worker needs a fine-grained GitHub token restricted to this repository with Contents read/write access:

```powershell
npx wrangler secret put GH_TOKEN --config cloudflare/wrangler.toml
```

The `/health` response exposes `publisherConfigured` as a safe boolean. It does not expose the token or prove that GitHub accepted it; check Worker logs and the actual daily JSON file as well.
